TOP 6 CRITICAL ISSUES (By Impact)
───────────────────────────────────────────────────────────────────────────────

🔴 #1: NO OFFLINE MODE / PENDING UPLOAD QUEUE
    If user captures meal offline, it's lost. No data recovery.
    Impact: HIGH (data loss risk) | Effort: HIGH
    
🔴 #2: NO RETRY LOGIC IN API SERVICE
    Transient errors (timeout, network blip) require manual user retry.
    Impact: HIGH (poor UX on flaky networks) | Effort: MEDIUM
    
🔴 #3: HOME SCREEN NO LOADING STATE ON FIRST LOAD
    App shows empty "0 calories" while data loads — bad perceived performance.
    Impact: MEDIUM (affects app perception) | Effort: LOW
    
🔴 #4: ANALYZING OVERLAY IS MISLEADING
    Shows progress steps but doesn't show "uploading" — users think it's slow.
    Actually: 15s upload time + 5s analysis = 20s, but UI suggests instant.
    Impact: MEDIUM (confuses users) | Effort: LOW
    
🔴 #5: NO ERROR HANDLING IN STORAGE.PERSIST()
    If AsyncStorage fails (out of space, corruption), data loss is silent.
    Impact: MEDIUM (rare but catastrophic) | Effort: MEDIUM
    
🔴 #6: CACHE INVALIDATION FRAGILE
    User captures meal → goes to Home → meal not visible for 1-2s.
    Home's useFocusEffect doesn't know cache is stale.
    Impact: MEDIUM (perceived UI lag) | Effort: LOW
